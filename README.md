总结：
  1.单一大模型均不能100%完成目标，需要多模型协作，实现和修改。
  2.逐个修改bug比长任务执行有个优势是：逐个修复可添加一些AI的细节考虑。
  3.长任务能较高准确完成目标的大模型：doubo-seed-code，mimo-v2.5,deepseek-v4-pro,glm5.1(以及高于这些模型能力的大模型)。
  4.首轮长任务执行推荐大模型：mino-v2.5, mimo-v2.5-pro, doubo-seed-code, glm5.1, deepseek-v4-pro(以及高于这些模型能力的大模型), 修改推荐：mino-v2.5，deepseek-v4-flash。
  5.多模型切换，降低token消耗，开发审查平衡。
  6.长任务执行需要清晰的执行目标，对开发任务需要多轮修改需求的情况可能不利于长任务执行。
  7.需求设计（架构->模块，需方便每个组成部分的添加和修改），需更懂工程范式，编程规范。
